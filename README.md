# 加油站班次交接 · 可重放班次账本

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript
- 启动：`npm install && npm run dev`
- 构建：`npm run build`（含 `vue-tsc` 模板类型检查）
- 测试：`npm test`（重放合并 / 旧数据迁移 / jsdom 端到端冒烟）

## 解决什么问题

两班交接时两台收银机同时录入、夜班断网后重复补录同一笔油款或退款，
旧页面把整份记录 JSON 直接覆盖写回，重开后不是少一笔就是多扣一次。

本项目把"交接台账"改成**只追加（append-only）的本机流水 + 确定性重放**：

1. **每笔销售、退款、复核都是一条流水**，带 `(deviceId, seq)` 本机流水号、
   业务时刻 `ts` 与确认时刻 `confirmedAt`。流水只追加，从不整体覆盖。
2. **合并靠重放，不靠覆盖**：打开页面、重连或崩溃重启后，把各设备流水按
   `(设备, 流水号)` 去重，按业务时刻排序重放，派生出每个班次的账目。
   - 同一业务单号双方录入、金额/升数/方式一致 → 识别为同一笔，**幂等合并**；
   - 金额不一致 → 进入**待核区**，双方金额、设备流水号、差异都保留，
     可"采用甲机 / 采用乙机 / 两笔剔除"，裁决本身也是流水；
   - 退款超额、退款找不到销售同样进入待核区。
3. **断网模型**：断网时流水照常落本机账，`confirmedAt` 留空；点击
   "模拟重连并补确认"后批量补确认时刻。未确认流水不允许关账。
4. **关账约束（可重放校验）**：班次必须已复核、无未裁决冲突、无待确认流水，
   且复核/关账晚于最后一笔业务。关账后若有断网补录到达，旧复核与旧关账
   自动失效，状态回到"待复核"，必须重新复核关账——未复核班次无法在页面上关掉。
5. **旧数组数据升级**：首次打开检测旧 key（`dfwlfront-7-shift`），
   逐条转成 `LEGACY` 设备流水，每处理一条写一次 checkpoint；升级中断后
   再次打开从断点继续。完成后旧数组改名备份为
   `dfwlfront-7-shift.legacy-backup`（可回滚），原 key 才清空。

## 页面能看到什么

- 顶部：当前收银机（甲机 REG-A / 乙机 REG-B）、在线/断网开关、重连补确认；
- 指标：在班/已复核/已关账数量、待确认流水笔数与金额、待核差异笔数与差异合计；
- 待核区：每笔冲突显示双方设备流水号、金额、升数、支付方式与差额；
- 班次卡片：**现金净额、电子支付净额、油品升数、待核差异**，
  以及开班/复核/关账时刻；展开可查看本班全部本机流水与确认时刻；
- 关账按钮在条件不满足时禁用，悬停与卡片下方明示受限原因。

## 存储结构（localStorage）

| key | 内容 |
| --- | --- |
| `dfwlfront-ledger.journal.v1` | 流水信封：`entries[]`（只追加）、各设备 `seq` 水位、种子标记 |
| `dfwlfront-ledger.migration` | 旧数组升级 checkpoint（总数/已处理/已生成流水），中断可续 |
| `dfwlfront-7-shift` | 旧版数组（升级完成后清空） |
| `dfwlfront-7-shift.legacy-backup` | 旧版数组备份（升级完成后生成，可回滚） |
| `dfwlfront-ledger.device` | 当前选中的收银机 |

核心代码：

- `src/ledger/types.ts` — 流水/冲突/班次视图类型
- `src/ledger/replay.ts` — 去重、排序、幂等合并、冲突检测、净额与关账规则（纯函数）
- `src/ledger/migration.ts` — 旧数组分条升级与断点续迁
- `src/ledger/store.ts` — 只追加存储、设备流水号、断网/重连
- `src/App.vue` — 台账页面
